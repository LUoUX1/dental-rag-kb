# 口腔医学 AI 知识库（多模态 RAG + 来源治理）

> 面向口腔临床场景的领域知识库：**BM25 + 向量混合检索**，支持文本 / 表格 / 影像三类知识，**每条回答都带来源依据**，
> 无法追溯到权威来源的内容会被显式标记为「待审核」。
> 后端 Express + 本地嵌入模型，**不依赖任何云端 API Key**。

## 为什么不是「直接问大模型」

临床问题是高风险的：模型可以给出看起来非常专业、但没有依据的答案。

所以这个项目的重点不是让模型更会说，而是三件事：

1. **每条输出都能追溯来源**
2. **没有权威来源，就不假装知道**（自动标记 `待审核` 并提醒）
3. **术语必须精确匹配** —— 牙位、术式名靠语义检索会漏

第 3 点决定了为什么必须做混合检索，而不是只用向量。

## 检索设计（这是整个项目的核心）

### 混合检索：BM25 词面 0.4 + 向量语义 0.6

```
final_score = 0.4 × BM25_score + 0.6 × cosine_similarity
```

- **BM25 权重 0.4**：专门救术语。口腔术语（具体牙位、术式名称）在语义空间里容易和近义词混淆，但词面匹配非常准。
- **向量权重 0.6**：负责「患者说‘牙一碰凉的就不行’」这类口语化表达，命中「牙本质敏感」。

### 集合配额检索：文本 5 / 表格 2 / 影像 1

不同类型知识的召回需求不同：文本片段可以多召回，表格和影像要少而准（影像召回错了会误导判断）。

```
textChunks  = hybridSearch(q, qVec, 5, ['text'])
tableChunks = hybridSearch(q, qVec, 2, ['table'])
imageChunks = hybridSearch(q, qVec, 1, ['image'])
```

### 双重阈值过滤（防「凑数式」召回）

```js
score >= 0.65 && score >= topTextScore * 0.7
```

绝对阈值 + 相对阈值同时生效：既过滤掉低分噪声，也防止某个片段因为整体召回质量差而「矮子里拔将军」。

### 同文档扩展（expandByDoc）

命中一个片段后，把同文档的相邻片段一起带出来——临床知识通常成组出现（诊断标准 + 鉴别诊断），拆开就没用了。

## 内容治理：这个项目最在意的部分

| 规则 | 实现 |
|---|---|
| AI 生成的参考框架**不得**作为资料源 | `source` 字段只允许真实指南 / 教材 / 病例 |
| 无权威来源内容必须显式标记 | 自动写入 `status: 待审核` 并在问答时提醒 |
| 知识卡片必须成结构 | 决策树 + 终止时机 + 预后量化，缺项不允许入库 |

> 一条设计原则：**宁可让用户看到「这条内容待审核」，也不让模型给出一个看似确定的错误答案。**

## 多模态向量库

- 三类集合：`text` / `table` / `image`，按 `data/vectors/<collection>/<docId>/` 分目录存储
- **本地嵌入**：`@xenova/transformers` + `Xenova/bge-base-zh`（走 hf-mirror，离线可用，无需 API Key）
- **版本备份**：覆盖前自动备份旧版到 `versions/`，保留最近 20 个文件，防止重建索引丢历史

## 知识库结构

按临床工作流组织，共 6 个环节：

| 目录 | 内容 |
|---|---|
| 01_接诊与沟通 | 主诉采集、沟通话术 |
| 02_检查与诊断 | 检查流程、诊断标准 |
| 03_治疗方案库 | 方案选择与对比 |
| 04_操作SOP | 标准化操作步骤 |
| 05_并发症与应急处理 | 风险识别与处置 |
| 06_持续学习 | 文献与更新 |

共 37 张知识卡片 + 维护规范 + 来源登记表；内容源为 Obsidian vault（Markdown + frontmatter），通过 `ingest/vault_sync.py` 同步。

## 架构

```
Obsidian Vault (Markdown + frontmatter)
        │  ingest/vault_sync.py
        ▼
   ┌─────────────┐
   │ chunker.js  │  按 text/table/image 分类切分
   └──────┬──────┘
          ▼
   ┌──────────────────┐
   │ embedding.js     │  Xenova/bge-base-zh（本地）
   └──────┬───────────┘
          ▼
   ┌──────────────────┐
   │ vectordb.js      │  多集合文件型存储 + 版本备份
   └──────┬───────────┘
          ▼
   ┌──────────────────────────┐
   │ routes/kb.js 混合检索 + 治理 │
   └──────┬───────────────────┘
          ├──→ Web 前端 (localhost:3002)
          └──→ Discord Bot (dental_bot.py)
```

## 技术栈

Node.js + Express ｜ @xenova/transformers（本地嵌入）｜ 自研文件型向量库 ｜ Python（Discord Bot、ingest 脚本）

代码量：约 1360 行 Python + 929 行 JavaScript。

## 运行

```bash
# 后端
cd server
npm install
cp ../.env.example ../.env    # 填入自己的值
npm start                     # http://localhost:3002

# 重建索引（从 Obsidian vault 同步）
python ingest/vault_sync.py

# Discord 机器人
python dental_bot.py
```

本知识库内容仅用于学习与技术验证，不构成诊疗建议。医疗决策请以执业医师判断与最新临床指南为准。
